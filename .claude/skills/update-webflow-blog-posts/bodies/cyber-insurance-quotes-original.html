Introduction‍

Cyber insurance quotes are carrier-issued pricing proposals summarizing what coverage a carrier will offer and at what price: aggregate limits per coverage category, per-incident retentions, sublimits for specific risk types, total premium, and commission. Brokers and MGAs receive competing quotes from multiple carriers for every submission, and the comparison work (matching limits, retentions, and sublimits across different carrier formats) is a manual bottleneck at volume.

‍

The extraction challenge compounds in two ways:
‍

  1. Carrier format variability. Beazley structures its cyber quote differently from Coalition, Chubb, or AXA XL, and a config built for one carrier's label conventions breaks on another.‍
  2. Document density. Cyber quote PDFs are often multi-page documents where the actual quote data sits in the first few pages, followed by carrier services guides and endorsement documentation. Extracting only the relevant fields requires anchoring precisely to the right sections.


Sensible handles this through carrier-specific layout configs. Cyber quotes are well suited to this approach: the structured Coverage Schedule tables and endorsement grids provide reliable anchor points that deterministic methods extract precisely, with no LLM calls and no prompt maintenance overhead on high-volume carriers. Each carrier gets its own config anchored to its label text and document structure, returning a normalized output schema across all carriers. For carriers without a layout config yet, a generalized LLM config handles extraction on day one without per-carrier configuration, covering the long tail of carriers that appear at low volume or in one-off submissions.
‍

This post walks through a Beazley cyber quote using a deterministic layout config. The same approach applies to cyber quotes from any carrier, and to other commercial lines documents (GL quotes, umbrella quotes, E&O quotes) that share the same structural characteristics.
‍

Anchor on coverage schedule section headers‍

Beazley's cyber quote opens with a multi-section Coverage Schedule. Each section header is a reliable anchor: the text is fixed, it appears on every Beazley cyber quote, and the values immediately follow in a consistent position.
‍

Here are the queries we'll use:


{
  "id": "aggregate_limit",
  "anchor": { "match": { "type": "equals", "text": "Cyber and Data Breach" } },
  "method": { "id": "row", "position": "right", "tiebreaker": "first" }
},
{
  "id": "retention",
  "anchor": { "match": { "type": "equals", "text": "Retention" } },
  "method": { "id": "row", "position": "right", "tiebreaker": "first" }
},
{
  "id": "premium",
  "anchor": { "match": { "type": "equals", "text": "Annual Premium" } },
  "method": { "id": "row", "position": "right", "tiebreaker": "first" }
}

‍

Extracted values:


{
  "aggregate_limit": { "value": "$1,000,000", "type": "string" },
  "retention":       { "value": "$10,000",    "type": "string" },
  "premium":         { "value": "$4,217",     "type": "string" }
}

‍

The Row method reads values to the right of each anchor. tiebreaker: "first" picks the nearest match when the anchor text appears more than once. These three fields — limit, retention, and premium — appear on every cyber quote regardless of carrier. They are the starting point for any cyber quote config.

Extract sublimits from the coverage table‍

Below the opening schedule, Beazley lists sublimits for individual coverage components in a two-column table: coverage name on the left, limit on the right.


{
  "id": "sublimits",
  "type": "table",
  "anchor": { "match": { "type": "equals", "text": "Coverage" } },
  "method": {
    "id": "fixedTable",
    "columnCount": 2,
    "columns": [
      { "id": "coverage",     "minX": 0,   "maxX": 3.5 },
      { "id": "limit",        "minX": 3.5, "maxX": 8.5 }

Extract endorsements‍

Beazley cyber quotes list active endorsements as a bulleted block following the coverage table. The Sections method extracts each endorsement as a structured item.


{
  "id": "endorsements",
  "type": "sections",
  "range": {
    "anchor": { "match": { "type": "equals", "text": "Endorsements" } },
    "stop":   { "match": { "type": "equals", "text": "Beazley Services" } }
  },
  "fields": [
    {
      "id": "endorsement_name",
      "anchor": { "match": { "type": "startsWith", "text": "•" } },
      "method": { "id": "documentRange", "includeAnchor": true }
    }
  ]
}

‍

Extracted values:


{
  "endorsements": [
    { "endorsement_name": { "value": "• Beazley Breach Response Services",     "type": "string" } },
    { "endorsement_name": { "value": "• Breach Coach® and Legal Services",       "type": "string" } },
    { "endorsement_name": { "value": "• Computer Fraud and Funds Transfer Loss", "type": "string" } },
    { "endorsement_name": { "value": "• Social Engineering",                      "type": "string" } },
    { "endorsement_name": { "value": "• Telecommunications Fraud",               "type": "string" } }
  ]
}

‍

Each bullet line is a section anchor. The DocumentRange method captures the full endorsement name including the bullet character. The stop anchor prevents the extraction from running into the Beazley Services section that follows.

Normalize currency output‍

Premium and limit values come back as strings ("$4,217"). To get a numeric value, add type: "currency" to the field. Sensible parses the string and returns a typed currency object:


{
  "id": "premium",
  "type": "currency",
  "anchor": { "match": { "type": "equals", "text": "Annual Premium" } },
  "method": { "id": "row", "position": "right", "tiebreaker": "first" }
}

‍

Extracted values:


{
  "premium": {
    "source": "$4,217",
    "value":  4217,
    "unit":   "$",
    "type":   "currency"
  }
}

‍

The typed output is downstream-ready: no string parsing, no regex, no post-processing step in your application code.
‍
‍

Add a fingerprint to protect against misrouting‍

Fingerprints prevent a config from running on the wrong document. For Beazley cyber quotes, two unique strings identify the format:


{
  "fingerprint": {
    "tests": [
      { "type": "includes", "text": "Beazley" },
      { "type": "includes", "text": "Cyber and Data Breach" }
    ]
  }
}

‍

If either string is absent, the config skips and the document falls to the next config in the document type — typically a generalized LLM fallback for the carrier long tail.
‍

Frequently asked questions

‍

What fields can be extracted from a cyber insurance quote?

Core fields include aggregate limit, per-incident retention, total premium, sublimits by coverage category, and active endorsements. A complete config also pulls policy effective dates, carrier name, form number, and waiting period for business interruption coverage.
‍

How accurate is automated cyber insurance quote extraction?

Deterministic extraction on a carrier-specific layout config is highly accurate: each field anchors to fixed label text, and output is traceable to source coordinates. Carrier-specific configs outperform general-purpose LLM extraction on structured Coverage Schedule tables and endorsement lists, where label positions are consistent across document versions.
‍

Can Sensible handle cyber quotes from multiple carriers?

Yes. Each carrier gets its own layout config. A generalized LLM config covers low-volume carriers on day one without per-carrier configuration. Fingerprinting routes each document to the right config automatically; no changes to your integration code when you add a new carrier config.
‍

How does Sensible handle multi-page cyber quote documents?

The fingerprint and field anchors operate across the full document. Fields anchored to section headers in the Coverage Schedule extract correctly regardless of page count; the stop anchor on the endorsements extraction prevents runoff into subsequent sections.
‍

Can Sensible extract from cyber quotes bundled with other documents?

The portfolio method segments multi-document PDFs before extraction runs. Carrier services guides, specimen forms, and endorsement documentation bundled with the quote are separated out; extraction runs only on the quote pages.
