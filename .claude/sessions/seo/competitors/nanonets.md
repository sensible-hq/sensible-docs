# Nanonets: top 20 docs pages and the phrases they target

Researched 2026-10-19. Sites: https://docs.nanonets.com (guides under `/docs/`, API reference under `/reference/`). Platform: ReadMe. Total pages found: 149 URLs in https://docs.nanonets.com/llms.txt (125 guides, 24 API reference). `sitemap.xml` returns 404; `/v4/reference/intro` now returns 404 too, so the earlier v4 link set is gone and llms.txt was used as the index.
Meta keywords usage: none on all 30 pages fetched. Every `<meta name="description">` except three (Model families, AI Agent Guidelines, File formats) is ReadMe's auto-excerpt of the first ~300 chars of body text, so most descriptions read as question-led FAQ openers ("What are instant learning models? …") rather than written summaries. Most pages have zero or one real H2; the title carries nearly all the targeting.
Selection criteria: one page per core concept, in this order: overview; extraction model types (instant learning, custom, pre-built, zero-shot); model families/LLM choice; training and table annotation; confidence; OCR; classification; workflow, approval rules, and human file review; file formats; webhooks and API authentication; the two integrations closest to Sensible's (email import, QuickBooks). Skipped: per-endpoint reference pages, billing/account pages, the 14 data-action formatting pages, per-document pre-built model pages (invoices, receipts, etc.), and per-destination export pages other than QuickBooks. Nanonets has no document-splitting page, so that slot was dropped.
Method: phrases are verbatim substrings (case-insensitive) of the title, meta description, H1, or H2s. "Borrowable" = not present (case-insensitive) in the mapped Sensible file's body.

## Patterns
- Pages are named after Nanonets' own model types and product objects ("Instant Learning Model", "Pre-Built Model", "Custom Model", "Zero Shot Model", "Model families", "Exports"), not after tasks. Task phrasing appears only in descriptions and H2s ("extract key information from documents", "capture data from tables", "flag files for review").
- Core vocabulary is ML/model-centric: model, train, training data, predictions, annotation, zero-shot, pre-trained. Sensible's docs have almost none of it: "zero-shot", "pre-trained", "custom model", and "approval rules" appear in zero Sensible doc files.
- Nanonets is now positioning on "agents" (overview: "turning complex business processes into agents", "agentic extraction", "AI agent guidelines"). That's the GEO vocabulary trend; Sensible's overview doesn't use "agent" or "business rules" anywhere.
- Review/approval is a first-class section (Approvals, Approval Rules, File Review, review stages). Sensible's equivalents (`validate-extractions.md`, `human-review.md`) use "validation" and "human review"; `validate-extractions.md` never says "approve" or "approval", and neither page says "approval rules" or "review stage" (`human-review.md` does use "approve" for the Approve Extraction button).
- Their SEO is weak: no meta keywords, auto-excerpt descriptions, few H2s, generic titles like "Overview" and "Authentication". Sensible doesn't need to beat their structure, only to cover the vocabulary.
- Caveat on mapping: some Sensible pages lack a phrase even though a sibling page has it ("document classification" appears in 5 other Sensible files but not `classify.md`; "confidence score" is in `accuracy-measures.md` but not `best-practices/confidence.md`).
