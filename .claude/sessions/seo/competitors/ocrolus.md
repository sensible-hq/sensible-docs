# Ocrolus: top 20 docs pages and the phrases they target

Researched 2026-10-19. Sites: https://docs.ocrolus.com (guides under `/docs/`, API reference under `/reference/`). Platform: ReadMe. Total pages in sitemap: 728 `<loc>` entries. `llms.txt` lists 545 pages; 413 of them are in the "Supported documents" section (per-document-type pages, many repeated per tax year, e.g. 7 separate Schedule C pages for 2018–2024), plus ~20 "Data types" pages.
Meta keywords usage: none. 0 of 23 fetched pages have `<meta name="keywords">`. SEO effort is visible only in `<title>` and `<meta name="description">` on ~6 marketing-flavored pages (rows 1–5, 11). On the rest, ReadMe autogenerates the title from the page name and the description from the excerpt or the first ~200 characters of body text.
Selection criteria: (1) Sections that the `llms.txt` index labels as core: Home, Quick start guides, Ocrolus API, Webhooks, Product guide pillars (Classify, Capture, Detect, Analyze), Supported documents, Data types, plus the two biggest integrations (Encompass, Plaid). (2) Concept or task pages, not per-endpoint API schema pages. (3) Pages with hand-written SEO titles and descriptions ranked higher. (4) At most 2 per-document-type pages (Bank Statements and 1040 Schedule C 2024), standing in for ~400 others. Fetched but cut as near-duplicates or thin pages: Getting started with SMB funding, Book status, Analyze (its description is the one-line `llms.txt` blurb and the page has no body headings).
Method: I took the H1 from the first `<h1>`. ReadMe renders body Markdown `#` headings as `<h1>`, so I counted the extra `<h1>`s as body headings along with the H2s (see the appendix). I removed sidebar nav H2s. "Borrowable" means the phrase doesn't appear anywhere (case-insensitive) in the mapped Sensible page's Markdown source.

## Patterns
- **Lending vocabulary, not extraction vocabulary.** Their hand-tuned titles and descriptions sell outcomes for lenders: "loan decisioning", "mortgage processing", "loan turnaround times", "borrower insights", "fraud detection for lenders". The words "parse" and "parser" never appear in the targeted fields, and "extract" shows up only 5 times across all 23 fetched pages (mostly "data extraction" in descriptions, plus "Extract results from a Book" and "extracted data").
- **Two title styles.** About six top pages use SEO-style `Keyword Phrase | Ocrolus` titles ("Automated Bank Statement Processing | Ocrolus Guide", "How Ocrolus Works | Intelligent Document Processing Explained"). Everything else keeps the bare nav label ("Classify", "Capture", "Overview", "Plaid"). This means their webhooks page is titled just "Overview", and their Plaid page's description is scraped nav text ("…View detail Importing Plaid audit copy token View detail"). That's weak SEO hygiene, and Sensible can beat it simply by writing excerpts.
- **"Intelligent document processing" and "document automation" are their umbrella terms.** They appear in three of the hand-tuned titles or descriptions. Sensible's `idp.md` already uses "intelligent document processing", but `welcome/overview.md` doesn't.
- **The long tail lives in per-form pages.** About 400 data-type pages target exact form names plus years ("1040 Schedule C (2024) - Profit or Loss from Business"), each with "Field descriptions", "Sample document", and "Sample JSON result" sections. That's a programmatic SEO play on form names. Sensible's closest equivalent is the configuration library, which isn't in these docs.
- **Feature names doubled as verbs.** Their product pillars are task verbs (Classify, Capture, Detect, Analyze). That gives them pages that match "classify mixed documents", "capture … data", and "detect document tampering".
- **Human-in-the-loop is a selling point.** "human-in-the-loop validation" is in the How It Works description, and Capture has a "Human-in-the-loop (HITL) workflows" heading. Sensible's human review page uses neither phrase.

## Top borrowable phrases
1. **human-in-the-loop** (and "HITL"): `docs/monitor and qa/human-review.md`. This is a standard industry term and the page doesn't contain it.
2. **intelligent document processing**: `docs/welcome/overview.md`. It's already in `idp.md`; the overview should use the umbrella term too.
3. **mixed PDF document** / **multi-page PDF**: `docs/document extraction/portfolio.md`. Pairs with the "split PDF" and "multiple documents in one PDF" phrases already in our draft.
4. **classify mixed documents**: `docs/document type classification/classify.md`.
5. **document automation**: `docs/Senseml reference/concepts/idp.md`. It's already in our draft for this page, and Ocrolus targets it in two titles.
6. **PDF bank statements** / **automated bank statement processing**: `docs/document extraction/library-quickstart.md`, or whichever Sensible page features bank statements. This is the highest-volume document type for lending.
7. **mortgage document processing** / **loan package**: `docs/document extraction/portfolio.md`. The draft has "loan packet" and "mortgage package"; "loan package" is the variant Ocrolus uses.
8. **logic-based rules**: `docs/monitor and qa/validate-extractions.md`. This is a plain-English synonym for JsonLogic validations.
9. **polling**: `docs/api/api-tutorial/api-tutorial-async-1.md`. The async tutorial never uses the word people search for ("poll for results").
10. **real-time event notifications** / **webhook URL**: `docs/api/api-tutorial/api-tutorial-webhook.md`.

Not borrowable for Sensible (no matching feature): fraud detection, document tampering, cash flow analytics, borrower insights, Encompass, Plaid.
