# B04: LLM vs. layout-based extraction

## Question

What's the difference between the LLM and layout-based approaches, and when should I use each?

## Answer

Based on the fetched docs, Sensible offers two extraction strategies — LLM-based and layout-based — and the choice depends on document variability, technical expertise, and tolerance for non-determinism.

**LLM-based extraction**

- You describe what you want in a plain-language prompt rather than writing spatial rules.
- Suited to unstructured, highly variable, or frequently revised documents (e.g., contracts, leases, research papers).
- Non-deterministic: the same document may return slightly different results across runs.
- Slower — each LLM call takes a few seconds.
- Can handle non-text images via the Query Group method with the Multimodal Engine parameter.
- Best for workflows that include human review or that are fault-tolerant.
- Key methods: **Query Group** (single facts), **List** (repeating items with unknown layout), **NLP Table** (tabular data).

**Layout-based extraction**

- Rules are written based on the spatial position of text: you anchor on known text and navigate relative to it.
- Suited to structured documents with a finite, predictable number of layout variations.
- Deterministic: same input always produces the same output.
- Faster in general.
- Cannot handle non-text images.
- Best for fully automated workflows that require predictable results and validation.
- Uses sections for complex repeating substructures.

**When to use each**

| Situation | Recommended approach |
|---|---|
| Free-form or highly variable document | LLM-based |
| Structured document with known layout | Layout-based |
| Either would work | Layout-based (for speed and determinism) |
| Non-text images in the document | LLM-based (Query Group + Multimodal Engine) |
| Automated pipeline requiring predictable output | Layout-based |
| Workflow includes human review | LLM-based is fine |

The two approaches can be mixed within the same SenseML config — for example, falling back from a layout-based query to an LLM-based one for the same field.
