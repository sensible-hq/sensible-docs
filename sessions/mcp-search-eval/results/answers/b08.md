# Q: Can it extract tables?

## Answer

Yes, Sensible can extract tables. There are three methods available, each with different trade-offs:

**NLP Table** (`id: nlpTable`) — Uses a large language model (LLM). You describe the table and its columns in natural language, and the LLM extracts and optionally restructures the data. This method is the most flexible: it handles variable column formatting and multi-page tables. It does not require an anchor. It is the slowest of the three methods. Best suited to tables with a header row where each row is a data element; not suited to tables where the header is in the first column.

**Fixed Table** — Layout-based. Extracts tables with a fixed number and layout of columns. Supports multiple pages, merged cells, and checkboxes in cells. Faster than NLP Table.

**Text Table** (`id: textTable`) — Layout-based. Matches tables based on column coordinates in inches (minX, maxX) and returns collated column contents. The fastest method since it skips table recognition entirely. Can handle unusually formatted tables other methods cannot recognize, but relies on line alignment and does not support merged cells or checkboxes.

**Feature comparison:**

| Method | Multi-page | Merged cells | Variable column formatting | Checkboxes |
|---|---|---|---|---|
| Fixed Table | Yes | Yes | No | Yes |
| Text Table | Yes | No | No | No |
| NLP Table | Yes | Indeterminate | Yes | Indeterminate |

**Additional notes:**
- For multi-page tables, Text Table and Fixed Table omit rows that precede repeated column headings after the first page.
- The older `Table` method is deprecated; use NLP Table with `rewriteTable: false` to replicate its behavior.
- For very large spreadsheets (tens of thousands of rows), use Cell Rows instead of table methods.
