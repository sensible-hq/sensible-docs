# e09

## Question

How does `angleFilter` in `removeLines` interact with different OCR engines (e.g., Google vs default) — is angle metadata available for all engines?

## Answer

### How `angleFilter` works in `removeLines`

`angleFilter` is a global parameter on Match objects (documented on the [Match object](https://docs.sensible.so/docs/match#global-parameters) page), not a parameter specific to `removeLines`. It is available to most Match types (excluding Boolean matches as a top-level parameter). When used inside a `removeLines` preprocessor's `match` object, it filters lines by their degree of rotation:

- `minAngle` / `maxAngle` define an inclusive range in degrees
- Positive values = counter-clockwise rotation
- Negative values = clockwise rotation
- Zero = horizontal text

The canonical use case shown in the docs is removing a rotated diagonal watermark by targeting lines rotated between 30 and 60 degrees:

```json
{
  "type": "removeLines",
  "match": {
    "type": "regex",
    "pattern": ".",
    "angleFilter": {
      "minAngle": 30,
      "maxAngle": 60
    }
  }
}
```

### OCR engine differences and angle metadata availability

The docs describe four OCR engine options (Amazon, Microsoft, Lazarus, Google) but make **no mention of angle metadata availability varying by engine**. There is no statement in the docs that any engine fails to provide angle/rotation data, or that `angleFilter` is unsupported or unreliable with any particular engine.

The one notable behavioral difference for Google OCR that is documented is unrelated to `angleFilter`: Google does **not** automatically merge words into lines, requiring the Merge Lines preprocessor to be used alongside it.

### What the docs do not say

The docs do not:
- State that angle metadata is available for all engines
- State that angle metadata is unavailable or degraded for any engine
- Warn that `angleFilter` behaves differently depending on which OCR engine is configured

The interaction between `angleFilter` and specific OCR engine choices is simply not addressed in the available documentation.

## Quality verdict

**2 / 5**

The docs answer *what* `angleFilter` does and provide a clear example in context of `removeLines`, but they are silent on the specific question of whether angle metadata is available across all OCR engines. The answer to the core question — engine-specific angle metadata availability — cannot be found in the docs, making this a partially answerable question at best.
