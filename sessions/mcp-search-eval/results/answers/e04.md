# e04

## Question

How does the `tiebreaker` comparison operator (`>`, `<`) interact with a `currency` type field — does it compare numeric values or raw source strings?

## Answer

By default, the `>` and `<` tiebreaker operators sort elements **alphanumerically using Unicode values** — meaning they compare raw strings, not numeric values. This is stated explicitly in the Method object docs:

> **comparison:** Returns the first or last element, sorted alphanumerically using Unicode values. If you want to compare numeric amounts and ignore non-numbers, then add a numeric type such as `type: currency` as a top-level parameter to the field.

So the interaction works as follows:

- Without a type: `>` / `<` do a raw Unicode/alphanumeric string sort. This means `"$9"` > `"$100"` because `"9"` > `"1"` lexicographically.
- With `"type": "currency"` set on the field: Sensible compares **numeric amounts** and ignores non-numeric characters. This is the intended path for meaningful monetary comparisons.

The currency type's output object has both a `source` (raw string, e.g. `"3 bil"`) and a `value` (numeric, e.g. `3000000000`). When `type: currency` is present on the field, the tiebreaker comparison uses the numeric `value`, not the `source` string.

**Source:** [Method object – Parameters table](https://docs.sensible.so/docs/method#parameters), tiebreaker row.
