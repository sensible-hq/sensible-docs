# e10

## Question
When two configs in the same document type have overlapping fingerprints and produce the same score, what's the tiebreaker?

## Answer
The docs do not describe a tiebreaker for equal scores.

The [Fingerprint mode](https://docs.sensible.so/docs/fingerprint-mode) page explains how Sensible selects a config after running extractions:

> After Sensible runs and skips extractions, it returns the extraction that ran with the highest-scoring config. Sensible calculates the score as follows: `score = num of non-null fields - penalties for validation errors or warnings`

The scoring formula is clear, but the documentation says nothing about what happens when two configs produce an identical score. No tiebreaker rule — such as config ordering, alphabetical name, or creation date — is mentioned on the Fingerprint mode page, the Fingerprint reference page, or the Config settings page.
