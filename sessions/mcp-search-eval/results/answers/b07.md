# B07

## Question

How do I handle documents from the same category that look slightly different from each other?

## Answer

In Sensible, documents in the same category that look different from each other are handled using **multiple configs** (templates) within a single document type. A document type (e.g., `bank_statements`) is the high-level category, and configs are the subtypes — for example, a `bank_of_america` config and a `wells_fargo` config within `bank_statements`.

### How Sensible selects the right config

When you submit a document for extraction, Sensible automatically classifies which config to use. There are two mechanisms:

**1. Fingerprints (recommended for layout-based configs)**

You can add a `fingerprint` to each config containing text that uniquely identifies that document variant. Sensible tests each fingerprint before running extraction; configs whose fingerprints don't match are skipped, saving processing time. Example fingerprint syntax:

```json
{
  "fingerprint": {
    "tests": [
      {"type": "startsWith", "text": "anyco"},
      "info@anyco.com",
      "life insurance quote"
    ]
  },
  "fields": []
}
```

Sensible requires 50% of fingerprint tests to match for a standalone document to pass.

**2. Fingerprint Mode (document type setting)**

The Fingerprint Mode setting in the document type's Settings tab controls how strictly Sensible applies fingerprint matching across configs. After running and skipping extractions, Sensible returns the result from the highest-scoring config (score = non-null fields minus penalties for validation errors).

**3. Fallback LLM configs**

For long-tail document variations — smaller providers or one-off layouts you can't anticipate — you can create a generalized LLM-based config as a fallback. Dedicated layout-based configs handle high-volume variants; the LLM config catches everything else.

### Summary of the pattern

1. Create one document type for the category (e.g., `bank_statements`).
2. Create one config per major document variant (e.g., per issuer or layout).
3. Add fingerprints to each config so Sensible can quickly identify which config matches the incoming document.
4. Optionally add a fallback LLM-based config to catch variants without a dedicated config.
