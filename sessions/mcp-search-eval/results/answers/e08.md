# e08 — lineFilters on vertical section range vs wordFilters on method object

## Question

What's the behavioral difference between `lineFilters` on a vertical section range vs `wordFilters` on the method object — is there a case where one works and the other fails?

## Answer

### `lineFilters` on a vertical section range

`lineFilters` appears in the **Range object** of a `sections` field (vertical direction only). According to the Sections page, for vertical sections this parameter:

> "Use[s] to ignore lines that span columns and break column recognition. For example, if the lines occur mid-column, use this parameter rather than a Stop parameter to exclude the lines. Sensible excludes the lines both from the output and from the SenseML search scope."

Key points:
- It takes a **Match object or array of Match objects** (pattern-based matching, not plain strings).
- It is **not supported** for horizontal sections.
- Its primary job is structural: it prevents multi-column-spanning lines from corrupting column boundary detection. As a side effect, the matched lines are also excluded from the field output and from the SenseML search scope.
- The docs explicitly say you don't need it if you use a Stop parameter.

### `wordFilters` on the method object

`wordFilters` is a **global method-level parameter** available to all methods (layout-based and LLM-based). According to the Method object page:

> "`wordFilters` | string array | Filters out the specified strings from the method results."

Key points:
- It takes a **plain string array** (exact string matching, not Match objects).
- It operates purely on **extracted output** — it strips matching strings from what the method returns.
- It has no awareness of document layout or column structure.
- It is available on any field's method, regardless of whether sections are in use.

### Behavioral difference and the case where one works and the other fails

The two parameters operate at completely different levels:

| | `lineFilters` (vertical section range) | `wordFilters` (method object) |
|---|---|---|
| Scope | Section boundary detection + SenseML search scope | Method output only |
| Input type | Match object (pattern-based) | String array (exact strings) |
| Layout effect | Removes lines from column recognition so columns aren't broken | None — purely post-extraction |
| Availability | Vertical sections only | Any method, any context |

**Case where `lineFilters` works and `wordFilters` fails:**

If a document has a vertical (columnar) section and a line of text spans across multiple columns mid-column (e.g., a subtotal row that cuts across a table grid), that line will break Sensible's column boundary detection, causing the entire vertical section to be misidentified. `lineFilters` on the range removes the line before column recognition runs, fixing the structural problem. `wordFilters` on a method cannot help here — it only strips strings from already-extracted output and has no effect on how columns are detected.

**Case where `wordFilters` works and `lineFilters` fails (or is unavailable):**

`wordFilters` works in any field context (horizontal sections, non-section fields, any method). `lineFilters` on a range is explicitly documented as "not supported" for horizontal sections, and it doesn't exist at the method level at all. So if you need to strip a known string from a method's output in a non-vertical-section context, `wordFilters` is the only option of the two.

**Summary:** `lineFilters` on a vertical section range is a structural tool that protects column recognition from disruptive lines and removes those lines from the search scope entirely. `wordFilters` on the method object is a string-removal post-processor on extracted output. They don't overlap in function: `lineFilters` is needed when spanning lines corrupt column detection (which `wordFilters` cannot fix), and `wordFilters` is needed for simple string removal from method output in any context (where `lineFilters` is not available).
