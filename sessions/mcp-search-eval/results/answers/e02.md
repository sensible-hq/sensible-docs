# e02: Repeated anchor match text within a section — does `requireStop` fully resolve this?

## Question

What happens when a section's anchor match text appears multiple times within a single section — does `requireStop` fully resolve this, or are there edge cases?

## Answer

### Default behavior (without `requireStop`)

By default (`requireStop: false`), Sensible ends the current section when it encounters the next match of the anchor's `match` text. If that text appears again inside what should be a single section, Sensible treats the second occurrence as the start of a new section, prematurely cutting the first section short. This is the core problem the `requireStop` parameter is designed to address.

### What `requireStop` does

Setting `requireStop: true` changes the boundary rule: each section ends only when it matches the configured `stop` parameter, not when the next anchor match is found. The `section-nuances` page states this explicitly under "Multiple anchors in section":

> "If you want to ignore multiple anchor matches inside the section, use the Require Stop parameter."

The `sections` reference page's parameter table confirms:

> "If true, each section ends when it matches the Stop parameter, instead of the default behavior of ending at the next starting line specified in the anchor's Match parameter. Configure this parameter for horizontal sections when the starting line repeats in each section, to avoid prematurely ending each section."

The inline code comment in the syntax example reinforces the mechanism: "if true, sections end at the stop match, even if an anchor match precedes the stop match."

### Known edge case: same-line matches are exempt

The docs explicitly carve out one scenario where `requireStop` is unnecessary:

> "You don't need to configure this parameter for matches that are on the same horizontal line as the anchor's Match parameter."

This implies that the premature-section-ending problem only occurs when the repeated match text appears on a different line from the anchor. If the repeated text is on the same horizontal line as the anchor match, Sensible already handles it correctly without `requireStop`.

### `requireStop` is horizontal-only

`requireStop` is not supported for vertical (columnar) sections. The parameters table marks it "not supported" in the vertical sections column. There is no documented mechanism for handling repeated anchor text within a vertical section.

### What the docs do NOT address

The docs do not describe behavior in the following cases:

- What happens if the `stop` text also appears multiple times within a section when `requireStop: true` — i.e., does Sensible stop at the first `stop` match or the last?
- Whether `requireStop` interacts with `offsetY` or `stopOffsetY` in any non-obvious way when multiple anchors appear.
- Behavior when there is no `stop` parameter configured but `requireStop: true` is set (logically undefined, but not discussed).

### Summary

`requireStop: true` is the documented solution for repeated anchor match text within a section, and it works by making the `stop` line — not the next anchor match — the authoritative section boundary. The one explicit edge case the docs note is that same-line anchor duplicates do not require `requireStop`. Beyond that, the docs do not enumerate further edge cases, so questions about nested stops, missing stops with `requireStop: true`, or vertical-section equivalents are unanswerable from the available documentation.

## Quality Verdict

**Score: 3/5**

The docs answer the primary question directly and usefully: `requireStop: true` is the fix, it works by making the stop line authoritative, and it is horizontal-only. The same-line exemption is a genuine, documented edge case that directly answers the "or are there edge cases?" part of the question.

However, the score is not higher because:

- The docs leave the inverse edge case unaddressed: what if the *stop* text also repeats within a section? This is a natural follow-up that a practitioner would immediately ask.
- There is no guidance for the vertical-sections equivalent problem — the docs just say "not supported" with no workaround.
- The question specifically asks whether `requireStop` *fully* resolves the problem. The docs do not make a definitive claim that it fully resolves it, and do not enumerate all scenarios where it might not. An honest answer from the docs is "it resolves the main case, with the same-line exemption noted," but the absence of deeper edge-case coverage leaves the question partially open.
