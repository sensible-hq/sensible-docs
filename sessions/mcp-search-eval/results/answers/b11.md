# Q: How do I get extracted data into Excel or a database?

## Answer

Sensible offers several paths for getting extracted data into Excel, databases, or other destinations.

### Excel and CSV

Sensible converts document extractions to Excel or CSV via two routes:

- **Sensible app**: After running an extraction, select documents and click "Download Excel."
- **API / Generate Excel endpoint**: Pass one or more extraction IDs to the Generate Excel method or endpoint.

The output structure follows these rules:
- A **fields sheet** holds single-value fields (one column per field ID, one row per document).
- **`<field_id>` sheets** hold multi-value outputs like extracted tables.
- **`<field_id>.<index>` sheets** hold complex repeating data like sections.

For **multiple documents or portfolio files**, Sensible appends each document as a new row in the fields sheet and prefixes non-fields sheets with a document index (e.g., `doc_0`, `doc_1`).

CSV output follows the same rules, using blank rows instead of tabbed sheets to separate content.

### Databases via Zapier

Sensible's Zapier integration can send extracted data into Airtable, Google Sheets, email, or any other Zapier-supported destination. The basic workflow:

1. Configure a Sensible trigger in Zapier (fires on each completed extraction for a document type).
2. Map Sensible field IDs to destination fields (e.g., Airtable column names).
3. Publish the Zap.

Limitations: Zapier handles single-value fields directly. For table/section output, enable the Excel output option on the Sensible trigger and use a spreadsheet integration (e.g., Google Sheets) to access rows. Zapier only works with single-document files; use the API or SDKs for portfolio files.

### Databases via API + Webhook

For automated, programmatic workflows, use the Sensible API. An asynchronous extraction workflow with a webhook works as follows:

1. POST to `/extract_from_url/{doc_type}` with a `webhook` object containing your endpoint URL.
2. Sensible calls your webhook when extraction status changes to `COMPLETE` (or review status changes to `APPROVED`), pushing the full `parsed_document` payload.
3. Your backend receives the push and writes the data to your database.

This avoids polling the `/documents/{id}` status endpoint.

### Summary of integration options

| Destination | Method |
|---|---|
| Excel / CSV file | Sensible app download or Generate Excel API endpoint |
| Airtable, Google Sheets, databases | Zapier integration |
| Custom database / application | API with webhook or polling, or SDKs |
