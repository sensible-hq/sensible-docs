# e03 — Portfolio segmentation: mixing fingerprint and LLM modes

## Question

Can you mix fingerprint-based and LLM-based segmentation within a single portfolio extraction, or is it one mode for the whole request?

## Answer

It is one mode for the whole request. The docs are explicit on this point: when creating a portfolio extraction request, you choose either **LLM mode** or **fingerprint mode** — not both simultaneously.

From the portfolio extraction steps in [Multi-document extractions](https://docs.sensible.so/docs/portfolio):

- **Enable segmentation** — you pick one of two alternatives: add a description to the document type (LLM mode) or specify fingerprints in each config (fingerprint mode).
- **Create the extraction request** — in the Sensible app you click **Portfolio** and specify either "fingerprint mode" or "LLM mode". Via the API, you set a single `segment_documents_with` field (e.g. `"segment_documents_with": "llm"`).

The two modes are presented in a comparison table as mutually exclusive alternatives for the same extraction. There is no option to apply LLM segmentation to some document types and fingerprint segmentation to others in the same request.

The granularity of each mode differs — LLM segmentation operates at the document-type level, while fingerprint segmentation operates at the config level — but that difference describes how each mode works internally, not a mixing mechanism between the two.

## Quality verdict

**4 / 5**

The docs answer the question clearly and unambiguously. The portfolio page presents LLM and fingerprint modes as a two-column alternatives table and describes the extraction request as a single-mode choice. The only reason this is not a 5 is that the docs never explicitly state "you cannot mix modes" — they simply never present mixing as an option, so the answer is conclusive by omission rather than explicit prohibition. A curious reader might still wonder if there is an undocumented workaround (e.g., two separate requests merged), but within the documented API the answer is clearly one mode per request.
