# e13

**Question:** Can preprocessors be conditionally applied based on document content, or do they always run unconditionally?

## Answer

The answer is nuanced: preprocessors themselves always run (there is no top-level "skip this preprocessor if condition X" parameter), but several preprocessors use content-based `match` parameters to scope *which pages* they act on. This is a form of content-conditional behavior, but it applies at the page level within a preprocessor's run — not at the level of skipping the preprocessor entirely.

Specific examples from the docs:

- **OCR preprocessor**: Has a `match` parameter (Match object or array) that causes Sensible to run OCR "solely on the page containing the matched text." The `pageLinesLimit` parameter also conditionally OCRs only pages with a specified number of embedded text lines or fewer. These make OCR processing conditional on page content.
- **Remove Page preprocessor**: Has a required `match` parameter — Sensible removes only pages that contain the matched text. The preprocessor runs on all pages but acts only where the match is satisfied.
- **Remove Lines preprocessor**: Has a required `match` parameter — removes only lines matching the pattern from all pages. The preprocessor always runs; removal is conditional on line content.
- **Deskew preprocessor**: Has a `matchAll` boolean that deskews all pages containing the Fixed Point lines, implying deskewing is scoped to matched pages.

The docs describe no mechanism to conditionally skip a preprocessor entirely based on a logical condition about document content. The document-variations page covers conditional execution at the field level (using a `conditional` construct) and config-level selection via fingerprints, but does not extend this conditional execution to preprocessors.

Preprocessors execute in the order they are defined in the `preprocessors` array; there is no documented `condition`, `if`, or `enabled` parameter that would allow a preprocessor to be bypassed based on document content.

**Summary:** Preprocessors always run, but several of them (OCR, Remove Page, Remove Lines, Deskew) accept `match` parameters that make their *effects* conditional on document content at the page or line level. There is no documented way to skip a preprocessor entirely based on a document-level condition.

## Quality verdict: 4/5

The docs give clear evidence for the page-scoping behavior (match parameters on OCR, Remove Page, Remove Lines, Deskew) and for conditional field execution. However, the docs don't explicitly state "preprocessors cannot be conditionally skipped" — this conclusion is inferred from the absence of any such parameter across multiple preprocessor reference pages. The answer is well-supported but the gap between "page-scoping" and "full conditional skip" could be stated more definitively if the docs addressed it directly.
