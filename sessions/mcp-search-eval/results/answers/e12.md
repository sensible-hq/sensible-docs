# e12

## Question
Does `requiredFields` on sections interact with extraction coverage scoring — i.e., do omitted sections count as missing fields?

## Answer

The docs address `requiredFields` and coverage scoring separately and do not explicitly describe an interaction between them.

**What `requiredFields` does:**
`requiredFields` is a parameter on a sections field. It takes an array of field IDs that must be non-null for Sensible to return a given section. If any listed field is null in a candidate section, Sensible **omits that section entirely** from the output array. Example from the docs: adding `"requiredFields": ["phone_number"]` to a claims section group causes any claim where `phone_number` is null to be dropped from the output.

**How coverage is calculated:**
Coverage = `(non-null fields extracted - validation penalties) / total fields extracted`

The docs note two relevant things about sections and coverage:
- "Sensible **includes** fields output in sections when calculating the coverage."
- Fields listed in the Suppress Output method are **excluded** from coverage.

**The interaction — what the docs say:**
The docs do not explicitly state what happens to omitted sections in coverage scoring. However, the coverage formula counts only fields that are actually output. Because `requiredFields` causes entire sections to be dropped from the output array rather than output as null, those sections' fields are never output at all — they are neither in `fields_present` (non-null) nor added to `total fields extracted` as nulls. The docs do not confirm or deny this interpretation, and there is no explicit statement that omitted sections count as missing (null) fields in coverage.

**Bottom line:** The docs do not address this interaction. Based on the coverage formula (which counts fields in the output) and the fact that `requiredFields` omits entire sections rather than nulling their fields, the most reasonable reading is that omitted sections do not inflate the null-field count — but this is not stated explicitly in the documentation.
