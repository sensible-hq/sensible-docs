# e05

## Question
When a JsonLogic postprocessor transforms the output schema, do validations run on the pre- or post-transform `parsed_document`?

## Answer

The docs do not explicitly state the execution order between the postprocessor and validations. However, the evidence strongly implies that validations run on the **pre-transform** `parsed_document`:

1. The [Validating extractions](https://docs.sensible.so/docs/validate-extractions) page states: "Validations have access to fields' values in the `parsed_document` object." All validation examples use `var` to reference fields in `parsed_document` (e.g., `{"var": "quote_rate.value"}`). There is no mention of validations accessing `postprocessorOutput`.

2. The [Postprocessor](https://docs.sensible.so/docs/postprocessor) page makes clear that postprocessor output lands in a **separate** `postprocessorOutput` object, distinct from `parsed_document`. The `parsed_document` continues to exist alongside it (unless `keepParsedDocument: false` is set). The postprocessor transforms `parsed_document` fields into a custom schema in `postprocessorOutput` — it does not replace or mutate `parsed_document` itself.

3. Together, this means validations reference `parsed_document` (the original extraction output), not the postprocessor's custom output schema. The postprocessor and validations operate on the same underlying `parsed_document`, so validations effectively run on the **pre-transform** field values.

**Caveat:** The docs do not contain an explicit statement about pipeline ordering (e.g., "validations run before/after the postprocessor"). The answer above is an inference from the structural separation of `parsed_document` and `postprocessorOutput`, and from the fact that validation conditions are written against `parsed_document` fields, not against `postprocessorOutput`.
