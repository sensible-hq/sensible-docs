# Q: What happens if a field isn't present in a document?

## Answer

Based on the fetched docs, when Sensible cannot extract data for a field — because the field is absent from the document or the method fails to find it — the field returns **null** in the parsed output.

Specific behaviors documented:

- **Null return as failure signal.** A field is considered "failed" if it returns null (or an empty array or undefined). A field is considered "passed" if it returns an empty string or 0, so those are NOT treated as missing. (Source: Fallback fields)

- **Anchor-based null for LLM methods.** For LLM-based methods, the `anchor` parameter is optional. If the anchored text is not found anywhere in the document, Sensible returns null for that field without running the LLM method at all. (Source: Field query object)

- **Fallback fields.** When a field returns null (or empty array/undefined), you can configure a fallback: define another field with the same `id` immediately after the failing field. Sensible will attempt to extract using the fallback instead. Fallbacks can chain and can mix field types (layout-based, LLM-based, computed, section groups). Limitations: fallbacks don't work across nested objects or within a Query Group method. (Source: Fallback fields)

- **Extraction coverage metric.** Null fields affect the extraction coverage score. Coverage is the percentage of non-null, validated fields versus total fields returned by a config. A field that returns null counts against coverage. (Source: Accuracy measures)

- **Validations.** You can write JsonLogic validations to detect null fields explicitly — for example, flagging an error when a required field like a quoted rate is null. (Source: Accuracy measures)
