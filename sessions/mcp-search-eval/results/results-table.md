## How the pipeline works

1. Agent calls `mcp__sensible-docs__search` → MCP returns a list of `{id, title, url}` results
2. Agent calls `mcp__sensible-docs__fetch` on each result ID → MCP returns raw doc text
3. Agent (Claude) reads the fetched text and synthesizes an answer

**"Docs returned by MCP"** = verbatim titles + URLs from the MCP `fetch` calls, as recorded in the raw JSON artifacts. Some agents saved fetched page data under non-standard keys (`fetched_docs`, `fetched_content`) rather than `fetched_pages`; titles and URLs are drawn from whichever key was present, supplemented by the answer `.md` files where metadata was missing.

**"LLM-synthesized answer"** = Claude's interpretation of the fetched doc content only. No prior knowledge used.

**"Pass/fail"** = assigned by domain expert. Ground truth.  
**"LLM pass/fail"** = assigned by Claude (LLM-as-judge). Treat as directional.
